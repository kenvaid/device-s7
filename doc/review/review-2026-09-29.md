# device-s7 代码评审（2026-09-29）

后续同步记录：`kenvaid/gos7` 已合并上游 `c54e650`，发布合并提交 `b01c5bde747688ce137d19ea44723ec0e7662e57`；device-s7 依赖已更新为 `v0.0.0-20260929065203-b01c5bde7476`。本报告的评审和复现记录针对同步前版本；本次同步保留连接清理修复、增加 ConnectContext 和回归测试，位地址等驱动正确性问题仍需单独修复。

## 按严重程度排列的发现

### 1. [P1] 位地址编码与当前 gos7 不兼容，读写访问不同 PLC 位

位置：[DBX 转换](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:664)、[非 DB 位地址](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:716)。

DBX 分支把 `Start` 预先转换为 `byte*8+bit`，且局部 `dbBit :=` 遮蔽外层变量，返回的 `Bit` 仍为 0。然而当前 gos7 的 `AGReadMulti` 再计算 `Start<<3 + Bit`；`AGWriteMulti` 则直接使用 `Start`，忽略 `Bit`。I/Q/M/V 分支返回字节偏移和 Bit，读取正确、写入错误。

| NodeName | 正确的报文位偏移 | 实际读取位偏移 | 实际写入位偏移 |
| --- | ---: | ---: | ---: |
| DB1.DBX100.0 | 800 | 6400（DBX800.0） | 800 |
| DB1.DBX1.3 | 11 | 88（DBX11.0） | 11 |
| Q12.5 | 101 | 101 | 12（Q1.4） |
| M29.1 | 233 | 233 | 29（M3.5） |

这直接影响状态采集和控制目标。当前样例中已有 `M29.1` 等位资源，DBX100.0 的既有单测则恰好断言了与新库读取约定冲突的 Start=800。

建议统一驱动内部的字节偏移/位偏移约定，并同时修正 gos7 多读、多写编码；仅修改 DBX 解析会修好读而破坏写。增加读取已知位及写后独立检查相邻位的协议级回归。

### 2. [P1] 批量写入的传输错误和 PLC 单点错误都可能返回成功

位置：[重试耗尽](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:374)、[单点错误返回](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:391)。

三次 `AGWriteMulti` 失败后退出外层循环，但最终执行 `return nil`。当整个事务成功返回、某个 `S7DataItem.Error` 表示拒绝写入时，代码返回的 `err` 恰好也是 nil。

已复现：连续三次 EOF 返回 nil；单点 `PLC access denied` 返回 nil；PDU 超限三次失败也返回 nil。上层 SDK 据此向调用方确认成功，实际设备可能未变更或仅部分变更。

建议传输错误直接返回；对单点错误构造含设备、资源、地址和批次的非 nil 错误，说明可能部分成功。不能保证多批次事务的原子性。

### 3. [P1] 无效读取被发布为零值，部分读取失败被发布为成功

位置：[无效地址占位](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:164)、[全批无效直接跳过](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:192)、[跳过单点错误](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:233)。

地址解析失败没有记入 `s7_errors`。整个批次无效时没有发送任何请求，但结果转换仍把初始化为零的 dataset 当作实测值。单点 PLC 错误、转换错误则被 `continue` 丢弃，其余结果压缩到响应切片，外层 err 通常仍为 nil。

已复现：`INVALID + Uint16` 不进行 I/O 却成功返回 0；两个资源中第一个被 PLC 拒绝，最终成功返回仅第二个资源。SDK 使用返回值直接构造 Event，不会补充丢失的资源，因此会得到静默缺项的采集事件。

注意：传输级读错误在复现中仍返回非 nil 错误，没有把这种情况错误归为“读取传输错误被吞掉”。

建议在访问设备前验证整个命令；明确命令级失败或受支持的逐项失败策略，禁止未读取数据和未说明的缺项被当作成功。

### 4. [P1] 固定 4 字节缓冲使 64 位读写静默损坏

位置：[读缓冲](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:123)、[写缓冲](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:284)、[64 位转换](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:790)。

代码声明支持 Uint64、Int64、Float64，地址解析也接受 VL/ML 等 8 字节区域，但每项仅分配 4 字节。gos7 Helper 用 binary.Read/Write 并只打印错误；SetValueAt 用 copy 静默截断，GetValueAt 在短缓冲下保持零值，驱动没有获得错误。

已复现：读取 Uint64 得到 `0, nil`；写 `0x0102030405060708` 只保留 `01 02 03 04`，错误仍为 nil。实际 8 字节写包剩余数据由底层零填充，不能保持原值。此外，地址指定的宽度与 req.Type 没有一致性验证，宽值写窄地址也会截断。

建议按实际地址/类型/数量分配缓冲并校验长度；使用返回 error 的编解码函数。不支持的组合应在 I/O 前拒绝。

### 5. [P1] 旧连接请求失败会删除并关闭已替换的新连接

位置：[更新连接](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:448)、[按名字关闭连接](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:556)。

请求持有旧 S7Client 的指针和锁，但失败时调用 `closeS7Client(deviceName)`，关闭的是此刻 map 中的对象。若 UpdateDevice 已发布新连接，旧请求就会删除新连接。新旧对象的 mutex 相互独立，无法防止这个交错。

已用“旧请求阻塞 → 发布替换连接 → 旧请求返回三次 EOF”的顺序复现，新连接从缓存消失。AddDevice/RemoveDevice 与在途请求也没有相应协调。

建议失败处理必须核对缓存仍指向失败的客户端，或采用连接代次/引用管理；生命周期操作需要与在途命令协调，不应只保护 map。

### 6. [P1] 短或残缺的 NodeName 会触发 slice 越界 panic

位置：[前缀切片](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:618)、[DB 地址切片](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:648)。

只排除了空串，就读取 variable[0:2]；DB 段未验证长度就读取 [3:]。已复现 `D`、`DB1.`、`DB1.X` 的 panic。这些字段来自设备 profile；HTTP 框架是否恢复 panic 不应代替驱动校验，后台采集路径同样可能到达解析器。

建议完整解析地址语法及范围后再构建 DBInfo，所有错误输入均返回可定位的错误。

### 7. [P2] 同一连接无队列上限和等待截止时间，未达到 Modbus 的过载保护

位置：[客户端锁](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:103)、[读请求加锁](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:133)。

S7 只使用普通 Mutex，等锁没有截止时间，也没有运行加等待请求数量限制。整个多批次命令、读取 50ms 重试等待、结果转换和日志均在锁内。一个慢设备会累积等待 goroutine，并占用 AutoEvent 工作线程；网络 Timeout 不包含等锁时间。

参考项目 [lockAddress](D:/workspace/iot/edgex/device-modbus-go/internal/driver/driver.go:67) 对同一地址的运行加排队请求限制为 100，超限返回错误。**100 是准入限制，不是同时进行 100 个网络事务。**

建议按连接增加有界准入、可取消的排队和停止信号；把无需保护连接的解析、转换放到锁外。接口无 context 时至少使用服务停止信号和内部队列截止时间，避免无限等待。

### 8. [P2] 冷启动或失效后并发请求会建立大量重复 TCP 连接

位置：[锁外创建连接](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:578)、[二次检查](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:584)。

二次检查只能保证最终缓存一个客户端，不能阻止多个 goroutine 同时 Connect。已复现同一 deviceName 的 8 个首次请求建立 8 条连接并完成握手后，才关闭其中 7 条。连接资源有限的设备可能在突发请求中拒绝新连接，随后请求反复触发创建。

建议按设备/连接标识合并连接创建（singleflight 或独立创建状态），保留不同设备建连的并行能力。参考 Modbus 用全局 clientMutex 去重，但它在网络建连期间也会阻塞其他地址的客户端获取，不适合原样照搬。

### 9. [P2] 更新、删除和停止没有完整关闭连接，Stop 也没有停止状态

位置：[Stop](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:405)、[UpdateDevice](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:442)、[RemoveDevice](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:457)。

UpdateDevice 覆盖旧连接且不关闭；RemoveDevice 仅删除 map；Stop 把 map 设为 nil，既不关闭现存连接，也不等待命令或设置停止标记。旧连接只能等 IdleTimeout 回收，IdleTimeout=0 时不会自动回收。停止期间仍完成创建的请求可能向 nil map 写入而 panic。

建议实现停止准入、等待/中断在途命令、逐个关闭连接的明确顺序；更新和删除主动关闭不再使用的连接，尊重 force 参数。

### 10. [P2] 固定 16 项批次没有按协商 PDU 大小拆分

位置：[读批次](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:115)、[写批次](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:275)。

“不超过 20 项”不能保证请求在协商的 PDU 内。当前 gos7 按报文总长和 PDULength 比较；16 个字节或位写项的请求长 307 字节，16 个 DWORD 写项长 339 字节，协商值为 240 时超限。读取响应长度及扩展后的大项数据也需要纳入预算。

已设置真实 gos7 Handler.PDULength=240 复现 16 项写入在发送前失败，驱动还因发现 2 返回成功。

建议依据当前库的 PDU 计数约定预算请求和响应大小，动态组批；确定性超限或配置错误不应重试三次并销毁健康连接。

### 11. [P2] 多个地址区域只有分支名，没有可用实现

位置：[空 case](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:619)、[Timer/Counter](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:696)。

Go 的空 case 不会自动贯穿后续分支。EB/EW/ED、AB/AW/AD、MB/MW/MD 都返回 Area/Amount/WordLength 为 0 的描述符，因此常用 MW/MD 地址并不可用。T10/C10 只设置区域和字长，Start、Amount 仍为 0，也不能访问指定索引。均已复现。

I/Q/V 的部分字节、字、双字路径可用，M 位路径可读；不应把这些推广成所有区域均完整支持。

建议实现各区域的规范语法和索引/长度，或者明确拒绝并记录不支持的区域。Timer/Counter 的编码也需独立定义，不能仅套普通整数转换。

### 12. [P2] 协议参数缺失被接受，缺省超时实际变成无限等待

位置：[ValidateDevice](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:478)、[覆盖库默认超时](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:521)。

cast.ToStringE(nil)/ToIntE(nil) 不报错，空的 s7 属性 map 可通过 ValidateDevice。缺少 Timeout/IdleTimeout 不会进入“默认 30s”分支，NewS7Client 读取为 0，覆盖 gos7 原有默认值；Timeout=0 时 Send 不设置有效截止时间。Host/Port 缺失、负数和越界的 Rack/Slot/位号也未完整拒绝。

已复现空 s7 属性 map 和 DB1.DBX0.8 被接受。地址整数用有符号 16 位解析还会拒绝较大的合法非负偏移，同时允许负数进入编码。

建议区分“键不存在”和“值转换失败”，应用统一默认配置，验证字段类型、Host 非空、端口/机架/槽位/位号/偏移范围；避免 ValidateDevice 原地修改传入属性作为隐式默认策略。

### 13. [P2] 空闲关闭后不自动重连，本次命令的三次重试全部必然失败

位置：[创建时唯一的 Connect](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:540)、[重试](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:200)。

固定 gos7 版本的 Send 发现 conn=nil 时直接返回错误，不自动 Connect。IdleTimeout 关闭底层连接后，驱动缓存仍在；下一次命令获取相同客户端，重试三次也不重新握手，最后才删除缓存，之后的下一条命令才能重建。读请求报错，写请求还受发现 2 影响假报成功。

样例 [S7-Device02](D:/workspace/iot/edgex/device-s7/cmd/res/devices/Simple-Device.yaml:23) 的 10s 采集间隔大于 5s IdleTimeout，直接具备这种触发条件。参考 grid-x/modbus 的 Send 会在发送前执行 connect，具有空闲后重连路径。

建议在发送前确认连接状态或重建失效客户端；区分连接错误、协议错误及单项拒绝。对写请求超时后的重试还需考虑设备已执行但响应丢失的情况，不能承诺恰好执行一次。

### 14. [P2] String 路径不能编解码，并会写入零值

位置：[读取 String](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:774)、[写值转换](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:833)、[Helper 调用](D:/workspace/iot/edgex/device-s7/internal/driver/driver.go:315)。

gos7 Helper 使用 encoding/binary，不支持直接读写 Go string。已复现非空字节读取成空串且 err=nil；写入 "test" 保持零缓冲并返回成功。没有字符串长度和 S7 STRING/WSTRING/raw bytes 编码约定。newCommandValue 的其他转换错误同样只记录日志后继续 I/O，复现类型不匹配时仍发送零数据。

建议单独实现有长度验证的字符串编码，或在命令验证时明确拒绝。所有参数转换错误必须阻断写入。Modbus 已有 stringRegisterSize 和寄存器字符串路径，但两种协议的字符串布局不能直接复用。

### 15. [P2] README 宣称的 NATS 构建入口没有把 tag 传给 go build

位置：[build-nats](D:/workspace/iot/edgex/device-s7/Makefile:22)、[实际构建](D:/workspace/iot/edgex/device-s7/Makefile:30)。

build-nats 仅设置 ADD_BUILD_TAGS=include_nats_messaging，但实际 go build 不使用 -tags，arm64 目标也不使用。README 还列出 docker-nats，而 Makefile 中没有这个目标。固定消息库在没有 tag 时使用会报错的 NATS stub。

建议像参考项目传递 -tags 及 Docker build arg，并补齐 docker-nats；构建验证应确认 NATS 实现已纳入依赖，而不只确认二进制能编译。

## 并发能力比较

| 维度 | device-modbus-go 当前实现 | device-s7 当前实现 | 评估 |
| --- | --- | --- | --- |
| 同一个端点/连接 | 按 host:port 或串口锁住整个命令；不同 UnitID 也共享地址锁 | 按 deviceName 对应的 S7Client 锁住整个命令 | 都串行；正常读写互斥已验证 |
| 不同设备/端点 | 地址锁不同可并行；新建连接期间全局 clientMutex 会阻塞客户端获取 | S7Client 锁不同可并行；连接创建在 map 锁外 | S7 的基础跨设备并行通过验证 |
| 同一个物理 PLC，多设备名 | 同地址通常仍串行 | 多个 deviceName 创建多条连接，可以并行 | S7 有多连接能力；必须测 PLC 限额，不能仅凭名称增加推断安全吞吐 |
| 单命令多资源 | 逐资源 GetValue/SetValue，部分 quantity 一次传多个连续位/寄存器 | 每 16 项 AGReadMulti/AGWriteMulti | S7 有减少往返的优势；16 项并不意味着 16 个独立并发事务 |
| 过载准入 | 每个地址运行加排队最多 100 条 | 无限制，无等锁截止时间 | S7 未达到参考保护水平 |
| 首次连接去重 | 全局锁内创建，能去重 | 连接创建后再竞争入缓存 | S7 突发请求会形成连接风暴 |
| 空闲后恢复 | 底层 Send 自动 connect | 底层 Send 报错，本次重试不重新 connect | S7 恢复能力不足 |
| 在途请求与生命周期 | 有关闭/停止/等待逻辑，但仍需单独审计停止竞态 | 旧请求误删新连接，更新/删除/停止漏关闭 | S7 未达到可靠生命周期水平 |

参考项目也不是无缺陷基准：其 stopped 和 workingAddressCount 的部分停止路径读取未使用对应锁；客户端创建持全局锁跨越网络连接。这些问题本次仅作静态观察，未执行其 shutdown 竞态复现，因此不应照抄实现或据此宣称参考项目完全并发安全。

在固定稳定连接、类型不超过 32 位、地址正确、负载可控的条件下，S7 可以具备相当的跨设备并发，批量读取还可能更省往返。但当前位地址错误以及错误漏报会使“返回得快”不等于“正确读写得快”。本次没有支持“总体吞吐低于/高于 Modbus”或“达到 2000 items/s”的测量证据。

## 功能完整程度

| 能力 | 参考项目 | 当前 S7 |
| --- | --- | --- |
| 基本标量读写 | 有寄存器/线圈路径及大量转换测试 | 8/16/32 位及 Float32 的部分地址路径可用 |
| 多资源读写 | 有；逐项失败向上返回 | 有多点 API 和拆批；错误结果不可靠 |
| 位/连续位 | Bool 及 quantity→Uint8/16/32/64；校验边界 | 单位读取部分可用，DB 位读取和非 DB 位写入错误；无等价 quantity 功能 |
| 64 位 | 有 64 位数字读写转换 | 类型分支存在，但固定缓冲破坏数据 |
| 字符串 | 有长度配置及寄存器字符串编解码 | 未实现有效编解码 |
| 原始类型与表示 | rawType、字节/字交换等 | 无等价的 rawType/长度/数量配置；S7 标准大端不要求普遍加入交换配置 |
| 地址区域 | 4 个 Modbus 主表及只读限制 | DB/I/Q/V 部分可用；MW/MD、E/A、T/C 路径不完整 |
| 连接协议 | TCP/RTU/ASCII/RTUoverTCP | ISO-on-TCP；这是协议产品范围差异，不是 S7 必须支持 Modbus 协议 |
| 自动发现 | 未实现 | 未实现，不算相对差距 |
| 回归基础 | 单测、模拟器、EdgeX E2E | 少量地址测试，缺少独立协议与 E2E 回归 |

数组、Binary、PLC 程序/时钟控制等不宜仅凭 EdgeX 类型常量或 gos7 API 就认定驱动支持；当前 HandleRead/Write 路径没有这些完整能力。本评审未把它们当作“已支持却损坏”的功能。

## 建议实施顺序和验收

1. 先修位地址、写错误返回、无效读/部分读策略、类型与缓冲校验、地址解析 panic。这些会直接造成错误数据和错误控制。
2. 建立连接生命周期管理：按连接去重创建、核对失败客户端身份、更新/删除关闭、停止准入和在途请求收敛、空闲重连。
3. 实施有界队列、排队截止时间和动态 PDU 拆批；补齐或明确拒绝区域、字符串、64 位、quantity 等功能；修复 NATS 构建。
4. 使用独立 PLC 模拟器/真实 PLC 做写后检查。测试 DB/I/Q/M/V 位地址、跨字节边界、符号与64位边界、字符串、16/17/32项、PDU=240/480、单点拒绝和传输断开。
5. 在有 C 编译器的环境运行 -race，同时触发首次建连、混合读写、更新、删除、停止。性能验收分别测单 PLC 单连接、多 PLC、多连接同 PLC、断网恢复与过载，记录正确成功率、items/s、命令 QPS、p50/p95/p99、goroutine/连接峰值及写入公平性。
